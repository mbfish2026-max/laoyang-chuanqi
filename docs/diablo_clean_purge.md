## 审核修复轮：MUST-FIX-03 / MUST-FIX-04（2026-10-26）

本节覆盖上文“一次性唯一备份、不覆盖”的旧实现说明。

- MUST-FIX-03（高16，兼高06、高07、高12、高14、中01、低02、低03）：删除全树 obsolete/禁属性键名删除器。仅角色根删除未分配 kp/sp、旧任务/资源/佣兵字段；仅角色根、eg、eg.history 转换并删除旧玩法整个对象；仅识别到装备对象才移除装备旧词缀、品质标记及原始快照。装备有效属性仍经过既有白名单/等价折算，付费次数与候选、UID、成长及战力补偿保留。真实 save/load 和 export/import 保留 eg.mj.runs=9、eg.uber.runs=8、ast.t.unique=1、cqSp.sp=300。
- MUST-FIX-04（高16、中02）：load 在 acctLoad 修改前、save 在 drainOld/清理前、export 在 save 前收集完整 GS 源账号：账号原文（含共享仓库）、全部角色原文、当前镜像和排行；save 另含尚未写盘的当前角色及账号。云 import 在清空 GS 前备份整个输入账号及现有本地账号。legacyRead 先只读收集全部角色、共享仓库及排行，再备份，再重写旧别名；移除该路径 cqRead 的提前创建别名副作用。单角色旧格式和排行独立清理也先备份，备份失败向上传播，中止上传。
- 恢复键仍为 cq-save-recovery-v1，但内容升级为 version:2 / entries。每条含 account、源 JSON 快照哈希、时间、raw；同账号+哈希+完整原文一致才去重，因此哈希碰撞不会漏备。新写入必须整串读回一致；损坏内容不能阻止后续备份。有效旧 v1.data 转为 legacy-v1 条目保留。恢复区不进 GS、不进云 payload。
- 备份上限为32条、entries JSON 最多4×1024×1024个UTF-16代码单元（最多约8MiB原文，不含小量封套）。按旧到新淘汰，单个新快照超限直接失败；浏览器更小配额也直接失败，源档不清理、不上传。采用单键 setItem 原子替换，失败不会先删旧备份。备份是有界恢复窗口，不承诺永久保留每个历史版本。

全仓同名排查：检查原 obsolete 集合和旧禁属性键的定义/消费者，除审核四个现行存档字段，还发现 skills/classes 的技能参数 sp、怪物 uniq/精英概率、bagux 的 lp 长按计时器、audio 的 unique/rune 音效等级、旧底材 staff、UI 的 cube 图标键及局部变量 sp；这些不应作为全树删除依据。后几类多数是运行常量/局部对象，并非已确认写盘损失；没有将它们冒称为已发生丢档。新增 custom 对象回归保留 runs/unique/uniq/sp/lp/staff/king/cube/runes/gems/keystones/affixes/ias/dr，防止恢复通用键名删除。装备 m 中同名禁止属性仍按装备规则处理。
